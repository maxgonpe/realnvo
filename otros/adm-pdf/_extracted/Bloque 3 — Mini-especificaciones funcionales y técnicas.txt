Bloque 3 — Mini-especificaciones funcionales y
técnicas
Banco y conciliación: B006 a B009

1. Propósito del bloque
Este bloque convierte los movimientos importados desde una cartola en registros operables dentro del
sistema.
Incluye:
• Consulta y filtrado de movimientos.
• Visualización detallada del dato bancario original.
• Clasificación administrativa manual.
• Distribución de un movimiento entre uno o varios destinos financieros.
• Cálculo de monto aplicado.
• Cálculo de saldo pendiente.
• Actualización del estado de conciliación.
• Auditoría de clasificaciones y aplicaciones.
Al finalizar el bloque, el sistema podrá responder:

¿Qué movimientos existen?
¿Qué información original entregó el banco?
¿Cómo se clasificó el movimiento?
¿A qué operaciones del sistema fue aplicado?
¿Cuánto queda pendiente de conciliar?

3. Secuencia funcional
B006 Lista de movimientos
→ B007 Detalle del movimiento
→ B008 Clasificación manual
→ B009 Aplicaciones bancarias múltiples
La dependencia es lógica:
1. Primero se localiza el movimiento.
2. Después se revisa su información original.
3. Luego se clasifica administrativamente.
4. Finalmente se distribuye entre operaciones del sistema.
No todos los movimientos deben clasificarse antes de ser aplicados cuando el destino sea evidente,
pero la interfaz debe ofrecer ambas acciones desde el detalle.

4.2 Clasificación administrativa
La clasificación identifica la naturaleza probable del movimiento:

PAGO DE CLIENTE
ANTICIPO DE FACTORING
ENTREGA DE FONDO
DEVOLUCIÓN DE CLIENTE
REEMBOLSO DE RENDICIÓN
GASTO BANCARIO
OTRO
La clasificación:
• No crea una conciliación.
• No consume monto.
• No vincula por sí sola un movimiento con una factura o rendición.
• Puede servir como sugerencia para una aplicación posterior.
• Debe conservar quién la realizó y por qué.

5. Diferencia entre B009 y B010
B009 — Nivel bancario
Distribuye un movimiento entre operaciones financieras:

Movimiento bancario
├── PagoCliente
├── FlujoFactoring
├── EntregaFondo
├── PagoLiquidacionRendicion
└── DevolucionPagoCliente

B010 — Nivel de facturas
Distribuye un pago de cliente entre una o varias facturas:

PagoCliente
├── Factura A
├── Factura B
└── Factura C
Por tanto, el flujo puede ser:

Movimiento bancario
→ AplicacionMovimientoBancario
→ PagoCliente
→ AplicacionPagoFactura
→ FacturaVenta
B009 no debe implementar todavía la distribución entre facturas.

5. Corrección requerida: límite del destino
La validación actual controla que las aplicaciones no superen el movimiento, pero también debe
comprobar que no superen la operación de destino.
Ejemplo incorrecto:

PagoCliente registrado: $500.000
Aplicaciones bancarias:
- Movimiento A: $400.000
- Movimiento B: $300.000
Total vinculado: $700.000
El sistema debe impedirlo.
Para cada destino:

Total de aplicaciones bancarias activas
≤ monto de la operación de destino
Esto aplica a:
• PagoCliente.
• FlujoFactoring.
• EntregaFondo.
• PagoLiquidacionRendicion.

• DevolucionPagoCliente.

6. Aplicación parcial a un destino
Debe permitirse que una operación de destino sea cubierta por más de un movimiento.
Ejemplo:

Pago de cliente: $1.000.000
Movimiento A aplicado: $600.000
Movimiento B aplicado: $400.000
Por tanto, no se impondrá una relación uno a uno.
Se controlará únicamente que el total no supere el destino.

Las 10 horas de B009 permiten implementar un MVP funcional apoyándose en:
