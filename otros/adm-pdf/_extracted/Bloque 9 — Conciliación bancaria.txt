técnicas
Banco y conciliación: B010 a B017

1. Propósito del bloque
Este bloque implementa la conciliación bancaria avanzada y el control formal de períodos.
Incluye:
• Distribución de un movimiento bancario entre varias facturas.
• Aplicaciones parciales de movimientos y operaciones.
• Cálculo de saldos pendientes.
• Reglas configurables de cruce automático.
• Sugerencias de coincidencias.
• Cruce manual asistido.
• Integración bancaria con facturación, rendiciones y factoring.
• Exclusión justificada de movimientos.
• Reversión de aplicaciones.
• Reapertura de conciliaciones cerradas.
• Cierre de períodos por cuenta bancaria.
• Conservación de snapshots y evidencia de cierre.
Al finalizar este bloque, el sistema podrá responder:

¿Qué operación explica cada movimiento bancario?
¿Cuánto del movimiento está aplicado?
¿Qué saldo continúa pendiente?
¿Qué facturas fueron pagadas con un depósito?
¿Qué fondos, devoluciones o reembolsos corresponden a un egreso o ingreso?
¿Qué movimientos fueron excluidos y por qué?
¿Quién revirtió una conciliación?
¿El período bancario puede cerrarse?

3. Orden técnico recomendado
La numeración de la Gantt se conserva, pero la construcción interna recomendada es:

→ B012 Reglas automáticas
→ B015 Exclusiones

Razón del orden
B011 define el motor común de:
• Monto aplicado.
• Saldo disponible.
• Estado parcial.
• Límites de origen.
• Límites de destino.
B010, B013 y B014 reutilizan ese motor.
B012 debe implementarse después de que los cruces manuales estén estabilizados. Las reglas
automáticas deben representar casos ya comprendidos y probados, no intentar definir el proceso antes
que los usuarios sepan cómo conciliar correctamente.

5. Principios comunes del bloque
5.1 No modificar la cartola
Los siguientes campos representan información original y permanecen inalterables:

fecha_operacion
tipo
monto
descripcion_original
referencia_bancaria
identificador_externo
contraparte
fingerprint
Clasificar, aplicar, excluir o reversar no debe modificar el registro importado.

5.2 No borrar aplicaciones
Una aplicación financiera no se elimina físicamente.
El ciclo será:

Aplicación activa
→ reversada o anulada
→ permanece en historial

5

5.3 Control de ambos lados
No basta con comprobar:

Suma aplicada ≤ movimiento
También debe comprobarse:

Suma recibida por el destino
≤ monto disponible del destino
Ejemplo:

Movimiento:
PagoCliente:

1.000.000 CLP
600.000 CLP

No puede aplicarse:
Movimiento → PagoCliente

800.000 CLP

Aunque el movimiento tenga saldo, el destino no puede recibir más de su propio monto.

5.4 Transacciones
Toda operación de conciliación debe utilizar:

transaction.atomic()
y bloquear los registros monetarios mediante:

select_for_update()
Como mínimo:
• Movimiento bancario.
• Operación destino.
• Aplicaciones activas.
• Conciliación del período, cuando exista.

5.5 Idempotencia
Confirmar dos veces la misma operación no debe crear aplicaciones duplicadas.

Permitir que un depósito bancario sea distribuido entre una o varias facturas, sin crear una relación
directa que omita el registro del pago del cliente.
Ejemplo:

Movimiento bancario:
Factura 1001:
Factura 1002:
Factura 1003:

1.000.000 CLP
400.000 CLP
350.000 CLP
250.000 CLP

Movimiento

→ tres AplicacionPagoFactura

3. Debe tener saldo disponible.

7. No se supera el pago.

14. El backend recalcula todos los montos.

La primera versión debe funcionar principalmente como:

Motor automático de sugerencias
no como conciliación autónoma sin revisión.
El modo automático podrá habilitarse únicamente para reglas:
• De alta confianza.
• Probadas.
• Versionadas.
• Autorizadas.
• Con rollback.

3. Criterios de coincidencia
Monto
• Exacto.
• Dentro de tolerancia.
• Suma de operaciones igual al movimiento.

Fecha
• Mismo día.
• Rango configurable.
• Fecha de pago versus fecha bancaria.

Referencia
• Coincidencia exacta.
• Coincidencia normalizada.
• Contiene número de factura.
• Contiene número de rendición.

RUT
• Contraparte bancaria.
• Cliente.
• Responsable.

12. Efecto del cierre
Después de cerrar:
• No se agregan aplicaciones ordinarias.
• No se anulan aplicaciones.
• No se crean exclusiones.
• No se revocan exclusiones.
• No se modifica la cartola.
• No se modifica el saldo.
• No se cambia el período.
Las acciones requieren reapertura.
